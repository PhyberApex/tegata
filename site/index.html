Authelia's users file, without the hand‑editing.

Authelia's file backend is a YAML file you edit by hand, with argon2 hashes you generate on the command line. Tegata is the admin UI for it: it writes users_database.yml for you, hands out invite and reset links, and refuses the one write that would lock every admin out of SSO.

Honest about a file it does not fully own

Authelia reads the users file. You, your editor and your backups can all still touch it. Tegata is built around that instead of pretending to be the only writer.

It notices edits made behind its back

The users file is hashed after every write. An edit by anything else shows a banner until an admin accepts the new baseline. It never blocks you — it only makes sure you know.

users_database.yml
users:  jonas:    displayname: Jonas Weber    groups: [family, media, admins]    disabled: false
The users database was modified outside Tegata. Accept current state

It shows what a group is actually granted

The Access Preview parses Authelia's configuration.yml — the {group} domain placeholder, group: subject rules and OIDC authorization policies — and summarises each group's reach, read-only. It also flags oddities, such as a policy no client references.

It refuses to lock you out

The Enabled-Count Guard stops a delete, disable or group change that would leave fewer than two enabled users, or empty a guarded group of its last enabled member. You can still go ahead — after you have confirmed you meant it.

The everyday work, without a terminal

What you would otherwise do with a text editor and a hash generator.

Users
Create, edit, delete, disable and re-enable. Reset passwords, hashed with argon2id.
Groups
Created in the UI, or seeded at startup from whatever groups existing users already carry. Deleting a group strips it from every user, invite and bundle that still names it, after a confirmation.
Group bundles
Named sets of groups — “Family member” — that expand into a plain group list when you create an invite or a user.
Invites
Expiring, single-use self-registration links, seven days by default. Optionally pre-filled, optionally emailed. The recipient picks their own username and password.
Reset tokens
A one-day link that lets one existing user set a new password. One outstanding token per user.
Email delivery
Invite and reset links go out over SMTP when configured — best-effort, never blocking the create. The copy-link and QR-code paths are always there.
Self-service
Anyone who signs in without the admin group gets a profile page for their own display name, email and password, and nothing more.
Observability
Prometheus metrics on /metrics, a runtime log-level switch, and /api/health.

Built to keep working when Authelia is down

Repairing Authelia's users file is what Tegata is for, so it cannot depend on Authelia to let you in. It does its own authentication and sits behind your reverse proxy with TLS, with nothing else in front.

  • OIDC is the everyday door. Anyone can log in with Authelia. Members of one group get the admin UI; everyone else gets self-service.
  • The password login is break-glass. One shared password, answered only from the networks you name and refused everywhere else before the password is even looked at.
  • The container is boxed in. It runs as root because Authelia keeps the users file root-owned — so the example drops every capability, forbids privilege escalation and mounts the root filesystem read-only.
  • It never writes Authelia's main configuration. configuration.yml is read for the Access Preview and nothing else.

Run it next to Authelia

Two volumes are the whole integration: read-write access to the directory Authelia mounts its configuration from, and a place for Tegata's own SQLite file.

  1. Generate the break-glass password hash with Authelia itself and put it in .env, in single quotes so Compose leaves its $ signs alone, alongside a session secret.
  2. Register Tegata as an OIDC client in Authelia, and make sure Authelia is watching the users file.
  3. Start the container behind your reverse proxy.

docker-compose.yml 
services:
  tegata:
    image: ghcr.io/phyberapex/tegata:2.1.1
    env_file: .env
    environment:
      - NODE_ENV=production
      - TEGATA_DB_PATH=/data/tegata.db
      - AUTHELIA_USERS_FILE=/authelia-config/users_database.yml
      - AUTHELIA_CONFIG_FILE=/authelia-config/configuration.yml
    volumes:
      - tegata-data:/data
      - ./authelia/config:/authelia-config
    read_only: true
    tmpfs: [/tmp]
    cap_drop: [ALL]
    security_opt: [no-new-privileges:true]
    restart: unless-stopped
